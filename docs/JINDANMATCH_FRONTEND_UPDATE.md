# 진단매치 FrontEnd 기능 개선

## 작업 브랜치
- feature/jang-create-project

## 작업 목적
의뢰인의 기업진단 의뢰 과정을 간편하고 직관적으로 개선하고,
회원/비회원 의뢰 및 업종별 진단 입력 흐름을 정리하였습니다.

## 주요 개선 내용

### 1. 기업진단 의뢰 화면
- 현재 사업 상태 선택
- 진단 분야 선택
- 업종별 Progressive 입력 방식 적용
- 상위 선택 변경 시 하위 입력값 초기화

### 2. 업종별 입력 플로우
- 건설업
- 전기공사업
- 정보통신공사업
- 소방시설공사업
- 산림사업법인
- 의약품
- 국가유산수리업
- 기타

### 3. 재무정보
- 자본금
- 현재 총자산
- 창업예정 시 예정 자본금

### 4. 의뢰 마감
- 오늘 / 내일 / 모레
- 오전/오후, 시, 분 선택
- 현재 시각 기준 최소 20분 이후부터 최대 48시간 이내 선택

### 5. 의뢰 내용 확인
- 사업 정보
- 진단 정보
- 재무 정보
- 의뢰 마감 정보
- 항목별 수정 기능
- 최종 의뢰 등록 확인 모달

### 6. 비회원 의뢰
- 회원가입 없이 휴대폰 번호 기반 간편 의뢰
- 향후 카카오톡 인증번호 연동 예정
- 휴대폰 인증 후 내 의뢰 진행상태 및 전문가 제안 조회 구조

### 7. 의뢰 완료 화면
- 의뢰 등록 완료 안내
- 비회원 휴대폰 번호 기반 조회 방식 반영
- 내 의뢰 확인 흐름 개선

### 8. 상단 메뉴 개선
- 견적 요청 메뉴 단순화
- 기업진단 의뢰하기
- 내 의뢰 확인하기

## 향후 연동 예정
- 카카오톡 휴대폰 인증 및 알림
- 전문가 제안/입찰 현황
- PG 결제
- 전문가 자동 정산
- 전자세금계산서
- 관리자 결제/정산/회원등급 관리

## 로컬 개발 환경
- FrontEnd: Vite
- FrontEnd Port: 5173
- Backend Local Port: 8081

## 실행

```bash
npm.cmd run dev
```

## 2026-11-05 개인 프론트 작업과 통합

- 기준: 개인 HEAD `5146956d`, 회사 작업 `fb4b6b5` (기능 `d8236bd`), 공통 조상 `b14545f`.
- 회사의 업종별 단계 입력, 사업 상태별 초기화, 재무 입력, 확인 화면, 최종 확인 모달, 메뉴 및 완료 화면을 반영했다.
- 개인의 공통 토큰 처리, 기업 ID 복원, 조회 오류 구분, 중복 저장 방지, 실제 내 의뢰 조회, 선정 상세, 관리자 심사 보완은 유지한다.
- 회원은 비회원의 임시 verifiedPhone 값 없이 기업 정보 조회/등록으로 진입한다.
- 회사 화면의 금액 필드 의미에 맞는 별도 변환을 적용하고 음수/지수/잘못된 쉼표/소수 자릿수 초과를 다른 숫자로 바꾸지 않고 거절한다. 창업 예정은 자본금을 보존하고 총자산은 전송하지 않는다.
- 비회원 인증·조회는 실제 API가 없으므로 준비 중으로 차단했다. 고정 확인번호 및 sessionStorage를 인증으로 사용하지 않는다. 기존 회사 설명의 휴대폰 조회는 완료된 서버 연동을 의미하지 않는다.
- 마감 시간 선택은 저장되지 않는 미리보기로 명시한다. 담당자명, 총자산, 소수 단위, 업종별 상세 값과 마감 저장 계약은 backend-api-requests.md의 API-011/012에 기록했다.
- 기존 회원 의뢰 API 호출은 유지하지만 신규 업종/목적과 전체 상세 값의 서버 수용 여부는 별도 확인이 필요하다.
- 검증: 단위 테스트 37개, TypeScript 검사 및 Vite 빌드. 브라우저에서 창업 예정→건설→업종 선택→소수 자본금→내용 확인→최종 모달→취소를 확인했다. 실제 운영 등록 및 서버 저장 검증은 수행하지 않는다.
